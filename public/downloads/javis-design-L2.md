### 0.2 一条要求怎么写
- 一条要求 = **什么情况下 + 司徒要做到什么（看得见的行为）+ 不做什么**。
- 表格 5 列：编号、要求（情况 → 行为）、不做、依赖、怎么验（验证方式 + 通过标准）。
- “依赖”列是反推需求表、更新互相影响表的依据。
- 不写“怎么实现”（不写模型、组件、机制）。
- 每个子目标 2–8 条，大多数 3–5 条；超过 5 条的注明理由。
- 维度条目只写用户怎么感受到；具体规则和红线只放在基础产品能力里一处，维度条目写“见基x”；**每条红线全文只出现一处**；没有对应基x 的红线（编造/伪出处、为照顾情绪改事实或故意不说、不实宣传、把明确删掉的加回、放宽围栏，见质2.1、情4.5、零1.1、交5.3、交5.4；审阅后“直接改画像”的红线移到基12.3）放在所属维度条目里，全文仍只出现一处。核心基础只写它必须具备的内容、质量和更新规则。

### 0.3 L2 和 L3 的分界
| | L2 定 | L3 定 |
|---|---|---|
| 验证方式 | 用哪一类方法、看什么现象 | 具体用例、数据集、步骤 |
| 通过标准 | **类型 + 方向 + 范围** | 具体数字 |

- 验证方式：**自动**（日志、规则检查）、**回放**（固定输入看行为）、**数据**（使用数据统计）、**模拟**（模拟用户评价，包括盲评）。“抽查”由更高一级的模型来做，服务人员不看用户的内容（P4；例外见下文“验证的前提”③）；需要人工评估时只用测试数据。
- 通过标准四类：

| 类型 | 写法 |
|---|---|
| 红线 | 零容忍。只留原则级的事 |
| 比例 | 方向（越高越好、越低越好、→0）+ 统计单位（按工作项、按回复） |
| 趋势 | 对比的对象（同一用户、同类工作项，前后对比）+ 方向 |
| 体验 | 谁来评、评什么 |

- 已经定了的数字照写（例如“10 分钟”）。
- **验证的前提**（审阅后，P-v13）：
  1. 除种子用户外，所有用户的统计在本机算好，只上报次数和比例，不上报内容；关掉统计就不上报。
  2. 人工打分只用测试数据，或由种子用户本人在场打分。
  3. 种子测试中，种子用户书面同意后，服务团队可当面和他一起看，或获取他的使用数据和指定文件（P-v13 种子测试例外）；封闭测试和正式用户不适用。
  4. 指标和标准值等种子测试后定（见第 8.4 节）。

### 0.4 工作项的定义
- **工作项**：用户要司徒办成的一件事，有一个用户想要的结果（交付物、结论或持续跟踪）。它是司徒做事、记上下文、让用户主导的基本单位。
- 不等于对话：一次对话可以有几个工作项，一个工作项可以跨多次对话、跨很多天。
- 不等于业务事项：“A 客户投标”是业务事项；“写投标方案”“查竞争对手报价”是工作项。
- 工作项 → 步骤，最多两层；复合的事拆成步骤，每一步各有一个工作类型。
- 状态：进行中、暂停、完成、放下。定期跟踪是一个长期的工作项。
- 改同一个交付物算重开；“照旧再做一份”算新的；一问一答演变成要成果时，算新的工作项，继承上下文并关联。
- **由司徒划分**，用户不用建、不用关；划分规则同归属判断。“工作项”一词不对用户出现。
- 一问一答也是轻量的工作项（服务上一个概念）；计点按种类区分（见基3、基14）。

### 8.4 种子测试要回答的问题（审阅后新增）
